# Circle Lens — working notes

Draw a circle twice with the mouse to open a magnifying lens at the pointer. It comes as a browser extension (`browser-extension/`, built on `shared/`), a native desktop app (`desktop/`, Go), and a script for websites (`web/`, npm `circle-lens`, also built on `shared/`). The feature started as the reading lens in BoundStretch. See README.md for use, layout and limits, and CONTRIBUTING.md for how changes come in. Anything specific to one person's machine goes in `CLAUDE.local.md` (git-ignored).

- **Open source (MIT).** Anyone can read and contribute: no personal paths, machine details, keys or private data in tracked files, commit messages or logs.
- **Toolchain.** Node 22 and Go 1.22 or later. Go is standard library only, no cgo; go-winres is fetched at build time to embed the exe's resources. On Windows, run npm and go natively (not from WSL against a Windows checkout), so `node_modules` gets Windows binaries.
- **Lean is the point.** The desktop app has no runtime dependencies, and nothing runs while the mouse is still. It uses no GPU stack: `internal/render` draws the lens in software, and its capture threads exist only while the lens is shown. Measure before and after any change to the desktop app, using `CIRCLE_LENS_LOG` (open-animation fps, longest gap, memory) and the `render` benchmarks (`go test -bench Compose -cpu 1,8`).
- **Frames follow the display.** `capture_windows.go` has a ticker (`DwmFlush`, once per refresh) and a capturer, on separate threads; the UI thread composes. Never put a capture or anything slow on the ticker. A frame draws at the pointer's current position over the newest capture.
- **Keep the two detectors in step.** `shared/circle-gesture.js` and `desktop/internal/gesture` are the same algorithm with the same constants: turn count, last-turn closure and roundness, the 250 ms pause reset, the window of 1.3 s per circle plus 0.4 s, the 64 px minimum, 95% of each turn, the gap after any open or close (`gap` setting, 0.6-5 s, default 1.5; `Hold`/`hold` for opens from elsewhere), and being spent after firing until the circling stops. Change both, or neither. Before and after any change, run `realism_test.go` (`go test -v ./internal/gesture`): it reports detection rates and accidental opens.
- **Motion matches BoundStretch.** The JS lens motion is in `shared/lens.css` and `shared/lens-view.js`; `desktop/internal/lens` reproduces it keyframe by keyframe, using the exact CSS curves from `internal/motion`. The values:
  - opening is a 560 ms spring from 55% scale, with opacity and blur done by 60%, and the label 140 ms late;
  - closing takes 340 ms: the glass shrinks first, fully opaque, then fades and blurs out from 45% of the way, ending at 30% scale;
  - zoom glides take 260 ms, with zoom from 1.2× to 4×.
- **Versions move together** ([RELEASING.md](RELEASING.md) has the steps and each channel's setup). A release bumps the root `package.json` and `web/package.json` (`web/build.mjs` refuses a mismatch), the pinned version in the CDN snippets (README.md, `web/README.md`, `web/src/script.js`, `web/AI_INSTRUCTIONS.md`) once that version is on npm (a snippet must never point at an unpublished version), and adds a CHANGELOG section; then tag `vX.Y.Z`. The release workflow publishes `web/` to npm when the `NPM_TOKEN` secret is set.
- **AI instructions stay true.** `llms.txt` (people who want a magnifier, in plain words) and `web/AI_INSTRUCTIONS.md` (coding agents adding it to a site) are followed literally by assistants. When install steps, shortcuts, options, asset names or supported systems change, update them in the same change.
- **The website lens copies the page, it never screenshots it.** `web/src/page-copy.js` clones the body into the lens. The copy must never load, play or run anything the page didn't: iframes, embeds and audio become empty boxes, videos a still frame.
- **Updates install code, so keep them strict.** The desktop app updates only from `update.Feed` (this repo's latest release). It installs only `CircleLens-Setup-<version>.exe` from `update.Downloads`, matching the size and SHA-256 digest in the API answer, and reporting that version with `-version`. Keep that asset name, the `-version` output and `-install -update` working, or installed copies stop updating. A test build (`-X main.instance=…`) updates only from `CIRCLE_LENS_UPDATE_FEED`; never let the real instance read a test feed. With "Update automatically" off, nothing may connect unless the person presses "Check for updates".
- **Settings are untrusted.** They go through `cleanSettings` (JS) or `settings.Parse` (Go) on every load.
- **Windows backend rules:**
  - The low-level mouse hook runs on its own locked thread (`hook_windows.go`) and only posts to the UI thread. Never do slow work in it, because it delays every mouse event on the system.
  - The lens window is left out of screen captures (`WDA_EXCLUDEFROMCAPTURE`). That is what lets the capture see behind it, and also why screenshots never show it: use `CIRCLE_LENS_FRAMES`.
  - Tray: left click opens the flyout (`flyout_windows.go`, compact, always dark), right click the native menu (`tray_windows.go`). Keep the two offering the same settings.
  - The flyout and the setup window (`setup_windows.go`) share the website's look: palette and pieces in `brand_windows.go`, drawing in `paint_windows.go`. Their static parts (`panelLayer`) are drawn once per showing; animation frames redraw only what moves. Check changes with `CIRCLE_LENS_PREVIEW` (test builds), which draws them offscreen to `CIRCLE_LENS_FRAMES`.
  - The keyboard hook (`keyboard_windows.go`) runs only for a double-tap shortcut or while recording. **Never log keys or anything typed from it, not even in debug builds**: its log once captured real typing. Test it through `onKeyAt` (`keyboard_windows_test.go`), never with injected keys while someone is at the machine.
  - Esc is not claimed globally; the shortcut (`internal/shortcut`, default Shift twice) opens and closes the lens.
  - Test builds take `-X main.instance=CircleLensTest`, so they run beside the copy in daily use (which may be elevated and so beyond `-quit`), with their own settings folder.
  - System DLLs load from System32 by full path.
  - A key-combination shortcut is registered while the app runs; the zoom keys (Ctrl +/−) only while the lens is open.
- **New platforms** add `*_darwin.go` / `*_linux.go` backends under `cmd/circle-lens` and reuse `internal/*`.
- **Installing.** The exe installs itself (`install_windows.go`): there is no installer framework. Per-user, under `%LOCALAPPDATA%\Programs`, with a Start menu shortcut made through COM (`link_windows.go`), an Uninstall entry under HKCU, and the start-up entry. Everything it creates is named after `instance`, so test builds (`-X main.instance=CircleLensTest`) install as "Circle Lens (Test)" and never touch the real copy. When testing, never use PowerShell's `Start-Process -Wait`: it waits for the installed copy the installer starts as well.
- **Releases.** `npm run package` builds both tools and writes `dist/CircleLens-Setup-<version>.exe` and `dist/circle-lens-extension-<version>.zip`. `desktop/build.mjs` runs go-winres first (icon, version information, manifest from `cmd/circle-lens/winres`). Pushing a `v*` tag makes GitHub Actions build both and publish the release (`.github/workflows/release.yml`).
- **Checks.** Run `npm test` and `npm run build` before committing; CI runs the same on every push and pull request. Conventional commit types. Bump the root `package.json` version, which the manifest and the exe both take, and add a section to CHANGELOG.md.
